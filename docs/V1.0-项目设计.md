# 云仓智配 V1.0 项目整体设计

本文件与 [yuncang-openapi.yaml](./yuncang-openapi.yaml) 共同构成 V1.0 基线。调整业务规则时，先同步修改两份契约，再修改实现。所有数量为非负整数，单据明细数量为正整数；时间统一为 ISO 8601，数据库存 UTC。示例路径统一以 `/api/v1` 开头。

## 第一部分：V1.0 系统边界

实现仓库、SKU 分类与 SKU、仓库库存查询、入库、出库、调拨、库存流水、盘点及低库存预警。单体 Spring Boot + MyBatis + MySQL；单次业务动作在一个数据库事务中完成。JWT 只承载用户身份和角色，服务端校验用户仍处于启用状态。库存表无通用增删改 API。

不实现供应商、客户、采购、销售、财务、真实物流、微服务或分布式事务。V1.0 核心业务不依赖 Redis、MQ；最终工程版可选用 Redis 加速单条库存查询，MySQL 始终是库存真实数据源。当前没有实际通知接收端，不接入 MQ。登录用户由初始化脚本或管理员线下维护；不提供用户管理 API。一个单据允许多个 SKU 行，同一单据内 SKU 不重复。一个操作处理整单，不做部分入库、部分出库、部分收货或部分盘点。

## 第二部分：角色与权限

| 角色 | 职责及接口权限 |
|---|---|
| ADMIN | 全部接口；维护仓库、分类、SKU；执行所有业务动作。 |
| WAREHOUSE_MANAGER | 查询所有数据；创建、预占、释放、取消、确认各类业务单据；执行盘点确认。 |
| WAREHOUSE_OPERATOR | 查询所有数据；创建入库/出库/调拨/盘点单；执行入库确认、出库预占/释放/确认、调拨预占/释放/发运/收货、取消；不能确认盘点。 |

V1.0 不做仓库级授权；所有角色可访问所有仓库。所有业务接口需要 JWT，只有登录公开。系统从 JWT 对应的已启用用户获取操作人，不接受客户端传入 operatorId。

## 第三部分：核心领域模型

Warehouse 是实体仓；SKU 属于一个分类并有全局 safetyStock。WarehouseStock 由 `(warehouse_id, sku_id)` 唯一确定，满足 `physical_stock = available_stock + locked_stock`，三者均不小于零。只在首次确认入库或首次调拨收货时创建库存行；创建仓库或 SKU 不生成空库存行。尚无库存行在查询中视为 0，但盘点仅针对已存在库存行。

Inbound/Outbound/Transfer/Stocktake 是业务单据，均有明细行；StockFlow 是每一库存行发生变化时追加的不可编辑审计记录。单据头的状态控制整单动作。调拨发运后，从源仓实际库存扣除，目的仓尚未增加；在途数量由 `transfer_order_item.quantity` 与单据 `IN_TRANSIT` 状态表达，不属于任一仓的 WarehouseStock。StockAlert 是当前低库存状态的物化视图，而非历史流水；当 `available_stock < sku.safety_stock` 时 ACTIVE，否则 RESOLVED。安全库存为 0 时不报警。

所有库存动作锁定单据和相关库存行，按 `(warehouse_id, sku_id)` 顺序加锁，检查状态与数量后在一个事务中更新库存、追加逐明细流水、变更单据状态并刷新预警。首次建库存行使用唯一键插入并处理冲突。读取流水时可按单据、仓库、SKU、类型筛选。每条流水保存三项库存的前值、后值和有符号差值、业务单据类型/ID、操作人、时间；同一动作每 SKU 一条。

## 第四部分：核心业务流程

```text
入库：创建 PENDING（库存不变）→ 确认：校验仓库/SKU 启用、整单明细 → 每行 physical/available +q → INBOUND 流水 → COMPLETED
出库：创建 CREATED → 预占：available -q、locked +q → RESERVED → 确认：physical -q、locked -q → COMPLETED
                         ↘ 释放：available +q、locked -q → CREATED；或取消并释放 → CANCELLED
调拨：创建 CREATED → 预占源仓：available -q、locked +q → RESERVED → 发运：源仓 physical -q、locked -q → IN_TRANSIT
                         ↘ 释放 → CREATED；或取消并释放 → CANCELLED       → 收货：目标仓 physical/available +q → COMPLETED
盘点：创建 DRAFT，记录各行系统三项数量及实盘 physical → 确认时核对快照仍一致且实盘 >= locked
      → delta = 实盘 - 原 physical；physical/available 同加 delta，locked 不变 → COMPLETED
      DRAFT 可取消；数据已变化时返回冲突，取消后重新建单。
```

取消规则：入库 PENDING 可取消；出库/调拨 CREATED 或 RESERVED 可取消，RESERVED 取消时原子释放；调拨 IN_TRANSIT 不允许取消，异常退货/丢失留待后续版本；盘点 DRAFT 可取消。完成/取消单据均不可再次操作。

## 第五部分：状态机

| 单据 | 当前状态 | 动作 → 目标状态 | 库存变化 | 流水 |
|---|---|---|---|---|
| 入库 | 新建 | create → PENDING | 无 | 无 |
| 入库 | PENDING | confirm → COMPLETED | 目标仓 physical/available +q | INBOUND |
| 入库 | PENDING | cancel → CANCELLED | 无 | 无 |
| 出库 | 新建 | create → CREATED | 无 | 无 |
| 出库 | CREATED | reserve → RESERVED | 源仓 available -q、locked +q | OUTBOUND_LOCK |
| 出库 | RESERVED | release → CREATED | 源仓 available +q、locked -q | OUTBOUND_RELEASE |
| 出库 | RESERVED | confirm → COMPLETED | 源仓 physical -q、locked -q | OUTBOUND |
| 出库 | CREATED | cancel → CANCELLED | 无 | 无 |
| 出库 | RESERVED | cancel → CANCELLED | 源仓 available +q、locked -q | OUTBOUND_RELEASE |
| 调拨 | 新建 | create → CREATED | 无 | 无 |
| 调拨 | CREATED | reserve → RESERVED | 源仓 available -q、locked +q | TRANSFER_LOCK |
| 调拨 | RESERVED | release → CREATED | 源仓 available +q、locked -q | TRANSFER_RELEASE |
| 调拨 | RESERVED | dispatch → IN_TRANSIT | 源仓 physical -q、locked -q | TRANSFER_OUT |
| 调拨 | IN_TRANSIT | receive → COMPLETED | 目标仓 physical/available +q | TRANSFER_IN |
| 调拨 | CREATED | cancel → CANCELLED | 无 | 无 |
| 调拨 | RESERVED | cancel → CANCELLED | 源仓 available +q、locked -q | TRANSFER_RELEASE |
| 盘点 | 新建 | create → DRAFT | 无，记录快照 | 无 |
| 盘点 | DRAFT | confirm → COMPLETED | physical/available +delta | STOCKTAKE_ADJUST，仅 delta 非零行 |
| 盘点 | DRAFT | cancel → CANCELLED | 无 | 无 |

所有未列出的转换返回 `ORDER_STATE_CONFLICT`（HTTP 409）。重复动作同样返回 409，不产生第二次库存变化或流水。客户端遇到网络超时后先查询单据状态与流水，再决定是否重试。

## 第六部分：数据库设计

通用字段：`id BIGINT` 主键、`created_at`、`updated_at`；单据还含 `created_by`、各动作 `*_by`/`*_at`。MySQL 8、InnoDB，数量 BIGINT，状态 VARCHAR，金额字段不出现。逻辑外键由应用校验，允许在开发环境加物理 FK；历史单据/流水不级联删除。所有列表索引兼顾 `created_at, id` 稳定排序。

| 表 | 核心字段与关系 | 唯一约束、索引 | status / version |
|---|---|---|---|
| `app_user` | `username,password_hash,role,enabled` | `uk_username` | `enabled`；无 version |
| `warehouse` | `code,name,address,enabled` | `uk_code`，`idx_enabled` | `enabled`；无 version |
| `sku_category` | `code,name,enabled` | `uk_code` | `enabled`；无 version |
| `sku` | `code,name,category_id,unit,safety_stock,enabled` → 分类 | `uk_code`，`idx_category_enabled` | `enabled`；无 version |
| `warehouse_stock` | `warehouse_id,sku_id,physical_stock,available_stock,locked_stock` → 仓/SKU；CHECK 非负且 physical=available+locked | `uk_warehouse_sku`，`idx_sku` | 无 status；V1 用行锁/条件更新，无 version |
| `inbound_order` | `order_no,warehouse_id,status,remark,created_by,confirmed_by/at,cancelled_by/at` | `uk_order_no`，`idx_warehouse_status_created` | PENDING/COMPLETED/CANCELLED；无 version |
| `inbound_order_item` | `order_id,sku_id,quantity` → 入库单/SKU | `uk_order_sku` | 无 status/version |
| `outbound_order` | 同入库头；另有 `reserved_by/at,released_by/at` | `uk_order_no`，`idx_warehouse_status_created` | CREATED/RESERVED/COMPLETED/CANCELLED；无 version |
| `outbound_order_item` | `order_id,sku_id,quantity` | `uk_order_sku` | 无 status/version |
| `transfer_order` | `order_no,source_warehouse_id,target_warehouse_id,status,remark,created_by,reserved_by/at,released_by/at,dispatched_by/at,received_by/at,cancelled_by/at` | `uk_order_no`，`idx_source_status_created`，`idx_target_status_created` | CREATED/RESERVED/IN_TRANSIT/COMPLETED/CANCELLED；无 version |
| `transfer_order_item` | `order_id,sku_id,quantity` | `uk_order_sku` | 无 status/version |
| `stock_flow` | `warehouse_id,sku_id,biz_type,biz_id,flow_type,delta_physical,delta_available,delta_locked,before_*,after_*,operator_id,created_at` | `idx_warehouse_sku_created`，`idx_biz`；合法的预占/释放循环可多次出现相同流水类型，不能对业务单据+类型加唯一键 | 追加写入，无 status/version |
| `stocktake_order` | `order_no,warehouse_id,status,remark,created_by,confirmed_by/at,cancelled_by/at` | `uk_order_no`，`idx_warehouse_status_created` | DRAFT/COMPLETED/CANCELLED；无 version |
| `stocktake_order_item` | `order_id,sku_id,snapshot_physical,snapshot_available,snapshot_locked,counted_physical` | `uk_order_sku` | 无 status/version |
| `stock_alert` | `warehouse_id,sku_id,available_stock,safety_stock,status,triggered_at,resolved_at` | `uk_warehouse_sku`，`idx_status_triggered` | ACTIVE/RESOLVED；无 version |

停用仓库或 SKU 前，拒绝仍有未终结单据引用（包括调拨 IN_TRANSIT）。分类停用前，拒绝有启用 SKU。停用不删除库存及历史。停用仓库/SKU 后不接受新单据及未完成单据的库存动作；已有预占仍允许释放/取消以清理锁定量。调拨在途收货要求目标仓和 SKU 仍启用，因此停用检查必须阻止在途引用。SKU 安全库存修改后，在同一事务内重算该 SKU 已存在库存行的预警；初次库存行创建、每次 available 改变后同步刷新。报警表只保留当前状态，历史变化由流水追踪。

## 第八部分：逐接口详细说明

统一响应 `ApiResponse<T>={code,message,data,traceId}`；成功 code=`OK`，错误 data=null。分页请求 `page>=1,size=1..100`，响应 `Page<T>={items,page,size,total}`。创建返回 201 与对应 VO；动作返回 200 与最新单据 VO；只读返回 200。所有接口错误统一含 `VALIDATION_ERROR`(400)、`UNAUTHENTICATED`(401)、`FORBIDDEN`(403)、`NOT_FOUND`(404)；下表仅列业务特有错误。写操作不存在空请求体，除创建/修改外动作均不带业务字段。禁用或状态冲突为 409。

| 接口组 | DTO / 查询 | VO | 状态约束、主要异常 |
|---|---|---|---|
| `POST /auth/login` | LoginDTO(username,password) | LoginVO(token,expiresAt,user) | `INVALID_CREDENTIALS`；禁用用户 `USER_DISABLED` |
| `GET /auth/me` | 无 | UserVO | 用户被禁用后 token 无效 |
| 仓库 create/update/list/detail | WarehouseCreateDTO(code,name,address)、WarehouseUpdateDTO(name,address)；列表 code/name/enabled/page/size | WarehouseVO / PageWarehouseVO | code 唯一 `DUPLICATE_CODE`；修改不变更 code、enabled |
| 仓库 enable/disable | 无 | WarehouseVO | 仅目标状态可执行；停用时存在未终结引用 `ACTIVE_ORDER_EXISTS` |
| 分类 create/update/list/detail | CategoryCreateDTO(code,name)、CategoryUpdateDTO(name)；列表 name/enabled/page/size | CategoryVO / PageCategoryVO | code 唯一；修改不变更 code、enabled |
| 分类 enable/disable | 无 | CategoryVO | 停用时有启用 SKU `ACTIVE_SKU_EXISTS` |
| SKU create/update/list/detail | SkuCreateDTO(code,name,categoryId,unit,safetyStock)、SkuUpdateDTO(name,categoryId,unit,safetyStock)；列表 code/name/categoryId/enabled/page/size | SkuVO / PageSkuVO | 分类须启用 `RESOURCE_DISABLED`；code 唯一；安全库存非负，更新安全库存重算预警 |
| SKU enable/disable | 无 | SkuVO | 停用时有未终结单据 `ACTIVE_ORDER_EXISTS`；启用要求分类启用 |
| `GET /stocks`、指定库存 | warehouseId、skuId、page、size；指定库存用路径参数 | StockVO / PageStockVO | 指定仓/SKU 必须存在；无库存行返回三项 0、`exists=false` |
| 入库 create/list/detail | InboundCreateDTO(warehouseId,items[{skuId,quantity}],remark)；列表 warehouseId/status/page/size | InboundVO / PageInboundVO | 新建校验启用仓/SKU、行唯一，`DUPLICATE_SKU_LINE`；创建不改库存 |

| 出库 create/list/detail | OutboundCreateDTO 同入库；列表 warehouseId/status/page/size | OutboundVO / PageOutboundVO | 新建校验启用仓/SKU；创建不保证当前库存足够 |
| 出库 reserve | 无 | OutboundVO | 仅 CREATED；逐行 available>=q，`INSUFFICIENT_AVAILABLE_STOCK`；多行原子操作【并发重点】【后续 Redis 改造候选】 |
| 出库 release | 无 | OutboundVO | 仅 RESERVED；释放整单锁定量【幂等重点】 |
| 出库 confirm | 无 | OutboundVO | 仅 RESERVED；扣 physical/locked，不再扣 available【幂等重点】 |
| 出库 cancel | 无 | OutboundVO | CREATED 直接取消；RESERVED 先释放再取消；完成不可取消 |
| 调拨 create/list/detail | TransferCreateDTO(sourceWarehouseId,targetWarehouseId,items,remark)；列表 sourceWarehouseId/targetWarehouseId/status/page/size | TransferVO / PageTransferVO | 两仓须不同且启用，SKU 启用；`SAME_WAREHOUSE` |
| 调拨 reserve/release | 无 | TransferVO | 与出库预占/释放相同，但流水为 TRANSFER_LOCK/RELEASE【并发重点】 |
| 调拨 dispatch | 无 | TransferVO | 仅 RESERVED；源仓 physical/locked -q，进入 IN_TRANSIT【幂等重点】 |
| 调拨 receive | 无 | TransferVO | 仅 IN_TRANSIT；目标仓 physical/available +q；无目标库存行则创建【幂等重点】 |
| 调拨 cancel | 无 | TransferVO | CREATED/RESERVED 可取消；RESERVED 自动释放；IN_TRANSIT 及终态不可取消 |
| 流水 list/detail | warehouseId/skuId/bizType/bizId/flowType/page/size；详情 id | StockFlowVO / PageStockFlowVO | 只读，无修改接口 |
| 盘点 create/list/detail | StocktakeCreateDTO(warehouseId,items[{skuId,countedPhysical}],remark)；列表 warehouseId/status/page/size | StocktakeVO / PageStocktakeVO | 仅已存在库存行；创建时服务端记三项快照；`STOCK_ROW_NOT_FOUND` |
| 盘点 confirm | 无 | StocktakeVO | 仅 DRAFT；当前三项须与快照一致，`STOCK_SNAPSHOT_CHANGED`；countedPhysical>=当前 locked，否则 `COUNT_BELOW_LOCKED`；delta=0 不写流水【并发重点】【幂等重点】 |
| 盘点 cancel | 无 | StocktakeVO | 仅 DRAFT，无库存变化 |
| 预警 list | warehouseId/skuId/status/page/size | PageStockAlertVO | 当前状态只读；默认只查 ACTIVE，指定 status 可查 RESOLVED |

所有订单列表与详情均返回明细。仓/SKU 停用、编码冲突等使用上述业务错误码；HTTP 409。数据库死锁与锁等待失败作为可重试的 `STOCK_BUSY`(409)，整笔事务回滚。V1.0 通过单据行锁、状态检查、库存条件更新和数据库事务保证并发下状态与库存一致。`stock_flow` 只对每条记录的主键唯一：同一单据可以合法地多次预占、释放，因此没有业务单据加流水类型的唯一约束。若未来存在实际通知接收端，可评估提交后异步通知；现有预警仍在同一数据库事务内刷新。所有确认类动作均是【并发重点】【幂等重点】。

## 第九部分：OpenAPI YAML

完整机器可读契约见 [yuncang-openapi.yaml](./yuncang-openapi.yaml)。该文件包含全部 50 个接口操作、参数、请求/响应 Schema、角色、状态前置条件、库存及流水影响、业务错误码和枚举。实现以 YAML 为接口最高契约，本说明解释其业务语义。

## 第十部分：Review

1. 无库存修改 CRUD；库存 DTO 没有可写的三项库存字段。
2. 所有状态变化均为明确动作接口；修改基础资料 DTO 不含 status。
3. 各动作后的 `physical=available+locked`：预占/释放只在可用与锁定之间转移；出库/发运同时减少 physical 与 locked；入库/收货同时增加 physical 与 available；盘点同时调整 physical 与 available，且不突破 locked 下界。
4. 入库创建和盘点创建均不改库存，确认才会产生实际变化。
5. 出库确认不二次减少 available；取消 RESERVED 与 release 共用释放语义。
6. 调拨发运只扣源仓，收货才加目标仓；在途由调拨单表达。
7. 重复确认、发运、收货由状态前置条件阻止，事务内先锁单据。
8. 每次实际库存变化逐明细写流水；盘点零差值不写无意义流水。
9. DTO、VO、表、流水类型和 YAML 枚举一致。
10. 唯一约束覆盖仓/SKU、单据编号和明细 SKU；流水允许同一单据多次预占/释放，按事务内状态校验防止重复动作。
11. 未引入部分履约、仓库级 RBAC、物流系统或分布式基础设施。
12. 预占和确认预留并发/幂等优化点；预警通知预留异步改造点，业务接口无需改名。
