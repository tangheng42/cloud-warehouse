# 云仓智配 V1.0 最终接口文档

**版本：** 1.0.0　**基础路径：** `/api/v1`　**格式：** JSON　**接口数：** 50

机器可读的字段定义、响应 Schema、逐接口错误码和角色规则以 [yuncang-openapi.yaml](yuncang-openapi.yaml) 为准。本文件给出调用顺序和库存业务规则。启动后可在 `/doc.html` 调试，原始契约地址为 `/openapi/yuncang-openapi.yaml` 和 `/openapi/yuncang-openapi.json`。

## 通用约定

- 除登录外，所有请求都需要 `Authorization: Bearer <token>`。登录响应的 `data.token` 即为令牌。
- 成功响应为 `{ "code": "OK", "message": "成功", "data": ..., "traceId": "..." }`；失败时 `data` 为 `null`。创建类接口返回 HTTP 201，其余成功接口返回 200。
- 分页接口使用 `page`（从 1 开始）和 `size`（1–100，默认 20）。响应 `data` 包含 `items`、`page`、`size`、`total`。
- 时间字段为带 `Z` 偏移的 UTC 时间。数量均为非负整数；业务单据明细数量必须大于 0。一个单据内不能重复传入同一 SKU。
- `ADMIN` 可执行所有操作；仓库、分类和 SKU 的写操作仅允许 `ADMIN`；盘点确认允许 `ADMIN`、`WAREHOUSE_MANAGER`。其他未特别注明的业务接口允许所有已登录角色。
- `409` 常见错误：`ORDER_STATE_CONFLICT`、`RESOURCE_DISABLED`、`ACTIVE_ORDER_EXISTS`、`INSUFFICIENT_AVAILABLE_STOCK`、`STOCK_SNAPSHOT_CHANGED`、`COUNT_BELOW_LOCKED`。锁冲突返回 `STOCK_BUSY`，可稍后重试。完整错误码见 OpenAPI 契约。

## 接口总览

下表路径均相对于 `/api/v1`；`{id}` 是对应资源的正整数 ID。`GET` 列表接口支持契约中列出的筛选参数和分页参数。

| 模块 | 方法与路径 | 用途 |
|---|---|---|
| 认证 | `POST /auth/login`；`GET /auth/me` | 登录、获取当前用户 |
| 仓库 | `POST /warehouses`；`GET /warehouses`；`GET /warehouses/{id}`；`PUT /warehouses/{id}`；`POST /warehouses/{id}/enable`；`POST /warehouses/{id}/disable` | 创建、查询、修改、启停 |
| 分类 | `POST /sku-categories`；`GET /sku-categories`；`GET /sku-categories/{id}`；`PUT /sku-categories/{id}`；`POST /sku-categories/{id}/enable`；`POST /sku-categories/{id}/disable` | 创建、查询、修改、启停 |
| SKU | `POST /skus`；`GET /skus`；`GET /skus/{id}`；`PUT /skus/{id}`；`POST /skus/{id}/enable`；`POST /skus/{id}/disable` | 创建、查询、修改、启停；修改安全库存会刷新预警 |
| 库存 | `GET /stocks`；`GET /stocks/warehouses/{warehouseId}/skus/{skuId}` | 库存列表、单仓单品库存 |
| 入库 | `POST /inbounds`；`GET /inbounds`；`GET /inbounds/{id}`；`POST /inbounds/{id}/confirm`；`POST /inbounds/{id}/cancel` | 创建、查询、确认、取消 |
| 出库 | `POST /outbounds`；`GET /outbounds`；`GET /outbounds/{id}`；`POST /outbounds/{id}/reserve`；`POST /outbounds/{id}/release`；`POST /outbounds/{id}/confirm`；`POST /outbounds/{id}/cancel` | 创建、查询、预占、释放、确认、取消 |
| 调拨 | `POST /transfers`；`GET /transfers`；`GET /transfers/{id}`；`POST /transfers/{id}/reserve`；`POST /transfers/{id}/release`；`POST /transfers/{id}/dispatch`；`POST /transfers/{id}/receive`；`POST /transfers/{id}/cancel` | 创建、查询、预占、释放、发出、接收、取消 |
| 盘点 | `POST /stocktakes`；`GET /stocktakes`；`GET /stocktakes/{id}`；`POST /stocktakes/{id}/confirm`；`POST /stocktakes/{id}/cancel` | 创建快照、查询、确认调整、取消 |
| 流水 | `GET /stock-flows`；`GET /stock-flows/{id}` | 查询库存变更记录 |
| 预警 | `GET /stock-alerts` | 查询库存预警当前状态 |

## 请求体和状态流转

| 单据 | 创建请求示例 | 状态和库存效果 |
|---|---|---|
| 入库 | `{ "warehouseId": 1, "items": [{ "skuId": 1, "quantity": 10 }], "remark": "采购入库" }` | `PENDING → COMPLETED`：确认时实体库存、可用库存各加数量，写 `INBOUND` 流水。`PENDING → CANCELLED` 不变更库存。 |
| 出库 | `{ "warehouseId": 1, "items": [{ "skuId": 1, "quantity": 3 }] }` | `CREATED → RESERVED`：可用减、锁定加，写 `OUTBOUND_LOCK`；释放回 `CREATED` 并写 `OUTBOUND_RELEASE`；确认到 `COMPLETED`：实体减、锁定减，写 `OUTBOUND`；`CREATED` 或 `RESERVED` 可取消，后者先释放。 |
| 调拨 | `{ "sourceWarehouseId": 1, "targetWarehouseId": 2, "items": [{ "skuId": 1, "quantity": 4 }] }` | `CREATED → RESERVED → IN_TRANSIT → COMPLETED`：预占源仓，发出时源仓实体和锁定各减，接收时目标仓实体和可用各加；流水依次为 `TRANSFER_LOCK`、`TRANSFER_OUT`、`TRANSFER_IN`。预占可释放；仅 `CREATED` 或 `RESERVED` 可取消。 |
| 盘点 | `{ "warehouseId": 1, "items": [{ "skuId": 1, "countedPhysical": 8 }] }` | 创建 `DRAFT` 时记录实体、可用、锁定快照；确认前重新比较三项。实盘数不得低于锁定数。确认后实体和可用各加差额，锁定不变；仅非零差额写 `STOCKTAKE_ADJUST`。`DRAFT` 可取消。 |

库存行仅由入库确认或调拨接收首次创建。每个单据动作整单原子执行；任一明细失败会回滚状态、所有库存变更、流水和预警。库存预警按 `safetyStock > 0 && availableStock < safetyStock` 判定 `ACTIVE`，否则为 `RESOLVED`。库存可用量变化或 SKU 安全库存变化后，预警在同一事务内刷新。停用仓库或 SKU 时，若有未终结单据引用则返回 `ACTIVE_ORDER_EXISTS`。

## 快速验证

1. `POST /auth/login` 获取 token。
2. 创建仓库、分类和 SKU；创建入库单并确认，然后查询 `/stocks` 与 `/stock-flows`。
3. 创建出库单，依次调用 `reserve`、`release`、再次 `reserve`、`confirm`；查询库存、流水和 `/stock-alerts`。
4. 创建跨仓调拨单，依次调用 `reserve`、`dispatch`、`receive`；核对两仓库存。
5. 创建盘点单并调用 `confirm`；若创建后库存变动，应重新创建盘点单。

本地自动验证运行 `mvn -pl cloud-warehouse-boot -am test`。测试使用 H2 内存库，不会修改本地 MySQL 数据。
